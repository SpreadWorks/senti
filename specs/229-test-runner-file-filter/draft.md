# Draft: 229-test-runner-file-filter

**開発種別:** feature
**目的:** テストランナーに個別テストファイル指定とパターン指定のフラグを追加し、ラベル集計・カテゴリ分類を維持したまま任意のテストファイルを実行可能にする。

## Requirements

優先度順:

1. **P1: `--file <path>` フラグ** — ユーザーが `--file <path>` を指定した場合、そのファイルをテスト対象に追加する。複数回指定した場合、すべてのファイルを union で実行する。
2. **P1: `--pattern <glob>` フラグ** — ユーザーが `--pattern <glob>` を指定した場合、glob に一致するファイルをテスト対象とする。一致ファイルが 0 件の場合、エラーで終了する。
3. **P1: 末尾 positional 引数** — フラグ以外の末尾引数をファイルまたはディレクトリとして解釈する。ディレクトリの場合は再帰的に `.test.js` ファイルを収集する。
4. **P1: 相互排他バリデーション** — `--file`/`--pattern`/positional（ファイル指定モード）と `--preset`/`--scope`/`--agent`/`--all`（ディレクトリ検索モード）を同時に指定した場合、エラーメッセージを表示して終了する。ファイル指定系フラグ同士は併用可（union）。
5. **P2: カテゴリ分類の維持** — ファイル指定モードで収集されたファイルも、既存と同じカテゴリ分類・ラベル集計パイプラインを通す。

## Scope Verification
- In scope:
  - `--file <path>` フラグの追加（複数回指定可）
  - `--pattern <glob>` フラグの追加（glob マッチによるファイル絞り込み）
  - 末尾 positional 引数によるファイル/ディレクトリ指定
  - 既存フラグとの相互排他バリデーション
- Out of scope:
  - 既存ディレクトリベース検索ロジックのリファクタリング
  - テストラベル集計・カテゴリ分類ロジックの変更
  - `--watch` や `--parallel` 等の別機能追加

## Impact on Existing Features
- テストランナー引数パース: 新フラグを追加。既存フラグのみ使用時の動作は変わらない
- フラグバリデーション: 新フラグの相互排他ルールを追加。既存ルールは維持
- 既存テスト実行フロー: フラグなし・既存フラグのみの場合の動作に変更なし

## Q&A
- Q1: ファイル指定モードと既存のディレクトリ検索モードの相互排他ルールはどうするか？
  - A1: 推奨: 両モードの混在を禁止する。根拠: 既存の `--agent` が他フラグとの併用を禁止している排他パターンと一貫性を保つ。ファイル指定系同士は union で併用可（`--file a.test.js --pattern 'tests/unit/flow/*'` のような用途を想定）。
- Q2: glob 展開にはどの仕組みを使うか？
  - A2: 推奨: 外部ライブラリを導入せず対応する。根拠: CLAUDE.md の「外部依存なし」ルール。
- Q3: `--file` で指定されたファイルが `.test.js` でない場合は？
  - A3: 推奨: `--file` は存在確認のみ行い拡張子フィルタを適用しない。根拠: ユーザーが明示的に指定したパスは意図的と判断する。`--pattern` と positional ディレクトリ展開には `.test.js` フィルタを適用する。
- Q4: ファイル指定モードでもカテゴリ分類・ラベル集計は維持するか？
  - A4: 推奨: 維持する。根拠: Issue #264 が指摘する問題は「ラベル集計を通らない」こと。ファイル発見方法が変わるだけで実行パイプラインは同一にする。
- Q5: テスト戦略は？
  - A5: 推奨: バリデーションロジックとファイル収集ロジックを unit テストで検証する。根拠: 既存テストがフラグバリデーションとディレクトリ検索を unit テストしているパターンに合わせる。検証項目: (1) 相互排他バリデーション — ファイル指定系+ディレクトリ検索系の併用でエラー、(2) `--file` による単一/複数ファイル収集、(3) `--pattern` による glob 展開、(4) positional 引数によるファイル/ディレクトリ指定、(5) 既存フラグのみの場合に動作変更がないこと。
