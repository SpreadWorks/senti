# Draft: Log Sensitive Information Masking

**開発種別:** ENHANCE (セキュリティ / ログ品質向上)

**目的:** Logger 経由で出力される全ログ（agent prompt log, git log, event log）の機微情報を一貫マスキングし、ログをコミット・共有した場合の漏洩リスクを低減する。

本 draft は意思決定段階（ブレスト段階ではない）。Q&A で確定した判断を記録する。

## 背景

Issue #178 (spec 176 gate-impl で指摘): git ログが cmd/stderr を無加工で記録しており機微情報マスキングがない。git 単独に入れるとアーキテクチャが歪むため、Logger 層に共通フックを置く。

## スコープ

- 対象: Logger 経由で書き出される全ログ出力
- 対象外: `process.stderr.write` による直接出力、ソースコード内のコメント、docs 生成物

## 要件（優先順位付き）

**P1 (MUST, 本 spec で必達):**

1. **R1:** When Logger がログエントリを永続化する時、shall 値に含まれる既知パターンの機微情報をマスク文字列で置換する
2. **R2:** When ログ値に以下の機微パターンが含まれる時、shall 該当部分をマスクする:
   - GitHub PAT (`ghp_`, `gho_`, `ghs_`, `ghr_`, `github_pat_` プレフィックス)
   - HTTPS 認証情報入り URL（`https://<user>:<token>@host/...` の user:token 部）
   - Bearer token（`Bearer <token>` の token 部）
   - AWS アクセスキー ID（`AKIA...`）
3. **R3:** When ログ値にプロジェクトルート（`SDD_WORK_ROOT`）外の絶対ファイルパスが含まれる時、shall 該当パスをマスクする。When パスがルート配下の時、shall マスクしない
4. **R4:** When マスク置換を行う時、shall 置換文字列として `***` を用いる
5. **R5:** When Logger 利用側コードが既存 API でログを呼び出す時、shall マスキングは Logger 側で自動適用される（呼び出し側の変更は不要）
6. **R6:** When ログ出力が行われる時、shall マスキングは常時有効であり、config フラグ等で無効化できない

**P2 (SHOULD, 運用上の制約):**

7. **R7:** When Logger が値を書き出す時、shall マスキング前の raw 値を別ファイルや別レコードに保存しない

## Q&A

各回答は「推奨（選択）→ 根拠」の順で記述する。根拠はソース種別を `[docs]` / `[guardrail]` / `[code]` / `[user]` で明示する。

### Q1: issue #178 の解釈

**推奨:** [1] 承認（Logger 層に共通マスキングフックを置き、git/agent/event 全ログにマスク適用）。

**根拠:** `[code]` Issue #178 本文「Logger 層に共通マスキングフックを入れる」および spec 176 gate-impl 指摘事項。

### Q2: マスキングパターン粒度

**推奨:** [1] 既知パターン辞書方式（+ プロジェクト外絶対パス）。汎用（高エントロピー）検出は採用しない。

**根拠:** `[docs]` CLAUDE.md「過剰な防御コードを書かない」「シンプル設計」方針。`[guardrail]` "Unambiguous Requirements" — 辞書方式は検出基準が明確で検証可能。汎用検出は誤検出で可読性低下。

### Q3: マスク後表現形式

**推奨:** [2] `***` 単純マスク。

**根拠:** `[user]` 情報量より簡潔性を選択（ユーザー判断）。

### Q4: 適用範囲

**推奨:** [1] Logger 全出力を対象とする。

**根拠:** `[code]` `event()` が free-form fields を受ける設計のため、allow-list 形式は非現実的。パターン数が限定的なので処理コストは alpha 運用量で無視可能。

### Q5: 設定制御と raw 保存

**推奨:** [1] 常時 ON、raw 保存なし。

**根拠:** `[docs]` CLAUDE.md「フォールバック値の抑制」。`[guardrail]` 本要件の目的は漏洩リスク低減であり、disable 可能化・raw 保存は目的と矛盾する。

## 代替案（却下）

- 汎用（高エントロピー）検出: 誤検出多で可読性低下
- config で on/off 可能化: 「本番 off 事故」リスク
- raw データ別ファイル保存: 漏洩面拡大で目的と矛盾
- `[REDACTED:PATTERN]` 形式: ユーザー判断で `***` を選択

## 既存機能への影響

- Logger 利用側コード: 変更不要（R5）
- ログスキーマ: 変更なし。値のみ置換
- 既存テスト: 機微パターンを含まないフィクスチャなので挙動変化なし

## テスト戦略（要件レベル）

- 各マスクパターンが検出・置換されることを検証
- プロジェクトルート配下のパスが非マスクであることを検証
- ネストしたオブジェクト内の文字列値もマスクされることを検証
- 非文字列値（数値、null 等）がマスク対象外であることを検証
- 一つの文字列内の複数マッチが全て置換されることを検証
