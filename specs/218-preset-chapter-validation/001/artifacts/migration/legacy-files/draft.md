# Draft: 218-preset-chapter-validation

**開発種別:** feature
**目的:** プリセットの章構成とテンプレートの静的整合性を既存コマンドの冒頭で検証し、ドキュメント生成パイプライン途中で不明瞭なエラーが出る状況を撲滅する。

## Scope Verification
- In scope:
  - **[P1]** When プリセット解決が完了した直後、 system shall 章構成とテンプレートの静的整合性を検証する
  - **[P1]** When 整合性検証を実行するとき、 system shall 章定義のエントリごとに、プロジェクト設定の配信言語すべてについて対応するテンプレートファイルの存在を確認する
  - **[P1]** When テンプレートの存在確認を行うとき、 system shall 生成時の解決範囲（プリセット継承チェーン配下のテンプレートディレクトリと、プロジェクトローカルテンプレートディレクトリ）を探索する
  - **[P1]** When 検証対象の章構成を決めるとき、 system shall プロジェクト設定に章の上書き定義があればそれを、なければプリセット定義の章を採用する
  - **[P1]** When テンプレートの欠落が検出されたとき、 system shall 重処理（スキャン・生成）を開始する前にエラーで停止し、欠落した章名・言語・探索済みディレクトリパス一覧を含むメッセージを出力する
  - **[P2]** When プリセット整合性テストが実行されるとき、 test suite shall 章-テンプレート整合性チェックを含める
  - **[P2]** If 章定義に記載のないテンプレートファイルが存在するとき、 system shall 警告のみ出力しエラー化しない（章を意図的に無効化する運用を許容する）
  - **[P3]** When validator の振る舞いを保証するとき、 unit test shall 欠落検出・プロジェクトローカル層の認識・設定上書きの認識を個別に検証する
- Out of scope:
  - 新規サブコマンドの導入（既存コマンドへの相乗り方針に従う）
  - 章構成のセマンティック検証（順序・依存関係・読者層マッチング等）
  - 章に依存しないテンプレート（エージェント向け・README 等）の検証
  - 既存プリセット整合性テスト群の挙動変更

## Impact on Existing Features
- 影響ありの既存機能:
  - 検証を追加する既存コマンド群: プリセット解決直後に検証が走る。整合したプリセット構成では挙動変化なし。不整合があれば重処理前に失敗する（従来は生成パイプライン中盤で失敗していた）
  - プリセット整合性テスト: テストケースが追加される。現行の組み込みプリセットがすべて整合していれば PASS。不整合検出時は本 spec 内で対象プリセットを修正する
- 影響なし:
  - ドキュメント生成パイプラインの scan 以降のロジック（早期 fail により到達しない）
  - プリセット整合性以外のコマンド群（flow / spec / その他）

## Q&A
- Q1: 検証の言語スコープは？
  - A1: プロジェクト設定の配信言語すべてで検証する。
  - 根拠: 既存コード（生成時のテンプレート探索ロジック）が言語別に existsSync を行うため、言語別検証でないと生成失敗と同じ粒度にならない
- Q2: テンプレートの探索範囲は？
  - A2: プリセット継承チェーン＋プロジェクトローカルテンプレート層。
  - 根拠: 既存コード（生成時の探索ロジック）と同じ 2 層構造を採ることで、validator が PASS なら生成も解決できる等価性を担保する
- Q3: プロジェクト設定による章上書きの扱いは？
  - A3: 実効章構成を検証対象とする（設定上書き＞プリセット定義の順で解決）。
  - 根拠: 既存コード（章順序解決ロジック）が同じ優先順位で上書きを解決するため、validator もこれに揃える
